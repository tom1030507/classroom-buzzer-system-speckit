# SF-01 設計決策

## 教師本機設定與角色隔離（FR-01，AC-16）

教師密碼透過本機 CLI 設定，SQLite 保存隨機 salt 與 scrypt 雜湊。教師及學生各使用不同 Cookie；每次變更操作檢查本機 Origin 與對應 Cookie 衍生的 CSRF token。學生憑證沒有教師角色權限。

## 加入與重連（FR-01，AC-04、AC-08、AC-15）

加入碼用於找到準備中的活動。活動內依去除首尾空白後的組名維持唯一性，後續身分由工作階段判定。原瀏覽器用相同加入前 Cookie 重試同一請求時，可透過資料庫內的 HMAC 種子找回同一工作階段，避免因回覆遺失而遇到組名占用。

## 退出準備中的活動（FR-01，AC-04、AC-08、AC-15）

原先因教師可同時建立多場活動，學生需要能離開停在準備中的活動。AC-24 之後同時只有一場未結束活動，退出主要用於改正組名後重新加入；是否保留由 #32 與另一組討論。退出由本人確認，伺服器同一交易內驗證階段及撤銷該組資料。資料庫外鍵連帶移除工作階段；活動維持原階段，其他組別的工作階段不受影響。

## 跨組規則：單一未結束活動、加入碼與組名（FR-01，AC-24，#32）

- **決定**：`createActivity` 在 `withTransaction`（`BEGIN IMMEDIATE`）內先查是否有 `status <> 'CLOSED'` 的活動，再新增。本機只有一個教師身分，所以不分工作階段。
  **理由**：檢查與新增同一交易，同時到達的請求只有一個成功。
  **考慮過**：partial unique index。舊的本機資料可能已有多場未結束活動，建立索引的 migration 會失敗，因此不採用；舊活動仍可從切換清單操作。
- **決定**：加入碼以 `crypto.randomInt` 逐字從 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` 取六碼，撞號時沿用 `ON CONFLICT` 重試。加入時的輸入檢查維持 1～32 碼英數字、不分大小寫。
  **理由**：先前發出的十碼加入碼仍可使用，錯誤的碼一律回 `INVALID_JOIN_CODE`。
- **決定**：組名長度在 `trim` 後以 code point 計，上限 30；資料庫維持原限制，既有較長組名保留。
- **決定**：教師頁以狀態列顯示伺服器的拒絕原因，活動階段改變時清除，按鈕保持可按。
