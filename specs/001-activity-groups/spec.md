# SF-01 活動與組別

負責人：tom1030507。對應 GitHub #2、#3、#4。跨組對齊的活動數量、加入碼與組名規則（AC-24）及準備中退出（AC-25）見 #32，依根規格 spec.md v1.2。

## 使用者情境

- **US1（#3，FR-01，AC-16）** 教師在伺服器本機設定密碼，從教師頁登入與登出。無教師工作階段、學生 Cookie 或無效 Origin／CSRF 的請求不能建立活動或執行教師操作。
- **US2（#4，FR-01，AC-04、AC-08、AC-15）** 教師建立準備中的活動並分享加入碼。學生在準備中填組名加入，刷新或重啟後從 Cookie 找回原組別。開啟後不能新增組別。另一瀏覽器不能以組名或聲稱的組別 ID 取得原工作階段。

- **US3（#24 審查、#32，FR-01，AC-04、AC-08、AC-15、AC-25）** 學生在準備中的活動按「退出目前活動」並確認。伺服器移除本人組別及工作階段，同一瀏覽器可用加入碼重新加入，例如改正打錯的組名。開啟或結束後提交舊頁面的退出請求應被拒絕。
- **US4（#32，FR-01，AC-24）** 教師同時只有一場尚未結束的活動，結束後才能建立下一場；另一個教師登入工作階段也受同一限制。學生以螢幕上的六碼加入碼加入，組名 1～30 個字元。

## 功能需求

- **FR-01 教師權限（AC-16）** 教師由本機 CLI 設定密碼，以教師 Cookie 操作活動與查閱組別。所有狀態變更透過同源與 CSRF 驗證。
- **FR-01 組別加入及重連（AC-04、AC-08、AC-15）** 後端以 Cookie 認定組別。只有準備中的活動可新增組別；同一活動組名唯一。重啟、刷新或原加入請求回覆遺失時可恢復同一工作階段。
- **FR-01 退出（AC-04、AC-08、AC-15、AC-25）** 已加入準備中活動的學生可撤銷自己的工作階段。從同一交易移除本人組別與 Cookie 對應資料；活動狀態與其他組別保留。`OPEN`／`CLOSED` 拒絕退出；退出與開啟經同一活動序列處理，舊工作階段與舊即時連線不可繼續取得活動資訊。
- **FR-01 單一未結束活動（AC-24）** 已有 `PREPARING` 或 `OPEN` 活動時，建立活動明確拒絕且不新增資料；本機單一教師密碼的多個登入工作階段視為同一位老師。多個建立請求同時到達時只有一個成功。
- **FR-01 加入碼與組名（AC-24）** 加入碼為六碼大寫英數字，字元集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（排除 0／O、1／I）。組名去除前後空白後限 1～30 個 Unicode 字元，同活動唯一。

## 成功標準

- **AC-04（加入部分）** 準備中建立或退出組別成功，開啟後的新增或退出請求被拒絕；退出後原 Cookie 無法重連。
- **AC-08（身分部分）** 同名或前端聲稱組別身分皆無法接管其他組別；學生只能取得自己的組別資訊。
- **AC-15（工作階段部分）** 瀏覽器刷新與伺服器重啟可恢復有效工作階段，同一瀏覽器重試同一加入請求只保留一組。退出後，同一瀏覽器可用加入碼重新加入準備中的活動。
- **AC-16（身分部分）** 缺少有效教師工作階段、來自不同 Origin 或缺少對應 CSRF 時，應拒絕受保護的操作。Cookie 設為 HttpOnly 及 SameSite=Strict。
- **AC-24** 同一老師含多登入工作階段最多一個未結束活動；碼為六碼指定字元；trim 後 1～30 Unicode 字元，同名並行僅一組成功。
- **AC-25** 準備中本人可退出、組別移除且原身分失效，可重新加入；`OPEN`／`CLOSED`、他人或偽造退出拒絕，已受理資料不變。

測試與驗收證據見 [驗收紀錄](acceptance.md)。

## 釐清

- 組名去除首尾空白後以 Unicode code point 計長度，在同活動以原字串比對。大小寫及全半形保留；同一工作階段由 Cookie 識別。退出後，原組名可依準備中的一般加入流程重新登記。
- 教師登入有效 12 小時，登出即撤銷。學生 Cookie 跨瀏覽器重啟保存，工作階段保存在 SQLite。
- 伺服器只有一個本機教師身分。教師重新登入後可繼續最近一次建立的活動。舊資料若留有多場未結束活動，仍可切換查看與操作，全部結束後才能建立新活動。
- 規則生效前建立的活動沿用原加入碼與組名；加入時仍接受 1～32 碼英數字。
