# 公平順位計算契約

`src/features/fair-ranking/fair-ranking.js` 匯出 `rankFair`，由 `src/features/results-export/ranking.js` 註冊為
`RANKERS.FAIR`，在 SF-03 的結束交易內由 `saveFinalResults` 呼叫。介面沿用
[SF-04 的順位計算契約](../../004-results-export/contracts/ranking.md)，規則取自根目錄 `spec.md` §4。

## 簽章

```js
/**
 * @param {{ unitId: number,
 *           submissions: { submissionId: number, groupId: number, acceptSeq: number }[] }[]} units
 *   依 units.position 由小到大排列；每個單位內的 acceptSeq 唯一，同一個 groupId 最多出現一次。
 * @returns {{ submissionId: number, unitId: number, finalRank: number }[]}
 *   每筆送出恰好一筆；依單位順序排列，單位內依 finalRank 由小到大。
 */
export function rankFair(units)
```

## 演算法

1. `wins` 為空的 `Map<groupId, number>`；沒有紀錄的組視為 0。
2. 依輸入順序逐一處理每個單位：
   1. 把該單位的送出依「`wins` 由少至多，相同則 `acceptSeq` 由小至大」排序（排序前先複製，不修改輸入）。
   2. 依排序結果給予 `finalRank` 1、2、3…。
   3. 若該單位至少有一筆送出，第 1 名的組 `wins` 加一。沒有送出的單位不改變任何組的 `wins`，也不產生輸出。
3. 回傳所有單位的輸出，依單位順序串接。

- 題組單位與單題單位一樣只有每組一筆送出，所以題組勝出只算一次。
- 沒有送出某單位的組不出現在該單位，也不影響其他組的順位。
- 不使用 `Date`、亂數、全域狀態或資料庫，不 `await`；同樣的輸入永遠得到同樣的輸出。
- 輸入由資料庫約束保證（`UNIQUE (unit_id, group_id)`、`UNIQUE (activity_id, accept_seq)`），函式不另行驗證。

## 不變式（不變式測試檢查）

1. 每個有 n 筆送出的單位，`finalRank` 恰為 1..n 各一次。
2. 每筆輸入送出恰好出現一次；輸入物件（即使被凍結）不會被修改。
3. 單位內的輸出順序符合（此前勝出次數，`acceptSeq`）的升序，其中此前勝出次數由輸出本身重新統計：
   該組在先前單位拿到 `finalRank = 1` 的次數。
4. 每個有送出的單位恰有一位 `finalRank = 1` 的勝出者。

## 測試向量

組別 ID：A = 1、B = 2、C = 3。`s(送出 ID, 組, 受理序號)` 簡寫為 `{ submissionId, groupId, acceptSeq }`；
輸出簡寫為 `[送出 ID → 順位]`。

### V1　AC-21：A 兩個單位都較快

| 單位 | 輸入（依序） | 說明 |
| --- | --- | --- |
| U1 | s(11, A, 1)、s(12, B, 2) | 勝出次數都是 0，依受理序號：A 第 1（勝出，A 勝出 1 次）、B 第 2 |
| U2 | s(21, A, 3)、s(22, B, 4) | A 已勝出 1 次、B 為 0 次：B 第 1（勝出）、A 第 2 |

輸出：U1 `[11→1, 12→2]`；U2 `[22→1, 21→2]`。受理順序仍是 A 在前，最終順位是 B 在前。

### V2　AC-22：勝出次數相同依受理序號，勝出較多者最後

| 單位 | 輸入 | 說明 |
| --- | --- | --- |
| U1 | s(11, A, 1)、s(12, B, 2)、s(13, C, 3) | A 第 1（A 勝出 1 次）、B 第 2、C 第 3 |
| U2 | s(21, A, 4)、s(22, C, 5)、s(23, B, 6) | B、C 勝出 0 次，C 的序號較小：C 第 1、B 第 2、A（1 次）第 3 |

輸出：U1 `[11→1, 12→2, 13→3]`；U2 `[22→1, 23→2, 21→3]`。

### V3　AC-22：無人作答的單位不加次數，題組只算一次

| 單位 | 輸入 | 說明 |
| --- | --- | --- |
| U1 | （沒有送出） | 沒有輸出，沒有任何組增加勝出次數 |
| U2（題組） | s(21, A, 1)、s(22, B, 2) | A 第 1（只增加 1 次，與題組題數無關） |
| U3 | s(31, A, 3)、s(32, B, 4) | A 已勝出 1 次、B 為 0 次：B 第 1、A 第 2 |

輸出：U1 `[]`；U2 `[21→1, 22→2]`；U3 `[32→1, 31→2]`。

### V4　沒有送出某單位的組不被排名

| 單位 | 輸入 | 說明 |
| --- | --- | --- |
| U1 | s(11, A, 1)、s(12, B, 2) | C 沒送出。A 第 1（A 勝出 1 次）、B 第 2 |
| U2 | s(21, C, 3)、s(22, A, 4) | B 沒送出。C 第 1（C 勝出 1 次）、A 第 2 |
| U3 | s(31, A, 5)、s(32, B, 6)、s(33, C, 7) | 勝出次數 A = 1、B = 0、C = 1：B 第 1；A、C 同為 1 次，A 序號較小，A 第 2、C 第 3 |

輸出：U1 `[11→1, 12→2]`；U2 `[21→1, 22→2]`；U3 `[32→1, 31→2, 33→3]`。

### V5　只有一組送出

三個單位都只有 A 送出：每個單位 A 都是第 1 名，輸出三筆 `finalRank = 1`。

### V6　依輸入順序而非 `unitId` 處理

把 V1 的兩個單位以相反順序輸入（先 U2、後 U1）：U2 先處理，A（序號 3）勝出；U1 再處理，A 已勝出 1 次，
所以 B（序號 2）第 1、A（序號 1）第 2。證明單位順序來自陣列順序（呼叫端負責依 `units.position` 排列）。

### V7　空輸入

`rankFair([])` 回傳 `[]`；全部單位都沒有送出時也回傳 `[]`。

## 呼叫端責任

- `saveFinalResults` 依 `units.position`、`accept_seq` 排序讀取資料後呼叫（SF-04 既有）。
- 呼叫端把回傳值寫入 `results`，`is_winner = finalRank === 1`；函式本身不寫入任何東西。
