## User Scenarios & Testing *(mandatory)*

### User Story 1 - 結束時保存結果並查看（Priority: P1，#14）

老師結束活動時，系統在同一個不可分割的步驟中保存每個單位的最終結果：速度模式下，每個單位依伺服器受理順序排名，
第一名勝出。結束後，老師與這場活動的各組學生都能看到各題各組的已受理答案、實際受理順序、最終順位、勝出組與答案；
無人作答的單位會明確標示。結果固定，不能新增或修改，伺服器重啟後也不變。

**Why this priority**: 寫回 Sheets 與 CSV 都以這份結果為唯一來源；沒有固定結果，後兩個故事都無法開始（spec.md §4、§9.1）。

**Independent Test**: 以兩組學生作答後結束活動，檢查老師與學生的結果畫面、重啟伺服器後再看一次，並嘗試修改結果。

**Acceptance Scenarios**:

1. **Given** 速度模式活動搶答中，A 組先送出第 1 題、B 組後送出，第 2 題無人作答，**When** 老師確認結束，**Then** 第 1 題顯示 A 組第 1 名勝出、B 組第 2 名，第 2 題明確顯示「無人作答」（AC-11）。
2. **Given** 題組單位由 B 組最先完整送出，**When** 活動結束，**Then** 題組內每一題都顯示 B 組為勝出組，各題答案依組內題序列出，整個題組只有一個共用順位（FR-08）。
3. **Given** 活動已結束，**When** 任何人嘗試新增、修改或刪除結果，或再次要求結束，**Then** 一律拒絕，結果維持不變（AC-11）。
4. **Given** 活動已結束且已保存結果，**When** 伺服器重新啟動，**Then** 老師與學生看到的結果與重啟前完全相同（AC-15）。
5. **Given** 活動在準備中或搶答中，**When** 學生透過任何頁面、API、即時事件或錯誤回覆查詢，**Then** 拿不到任何結果或其他組的資料（FR-05、AC-09）。
6. **Given** 保存結果的過程發生錯誤，**When** 老師結束活動，**Then** 結束失敗、活動仍為搶答中，不留下部分結果（spec.md §4）。

### User Story 2 - 預覽並寫回原雲端 Google Sheets（Priority: P2，#16）

活動結束後，老師先預覽要寫回的題號、勝出組、答案與目標格。系統在預覽時與實際寫入前都重新讀取雲端試算表，
確認每個目標格仍是原本的標記，或已經是本次要寫入的相同內容。老師確認已暫停其他人編輯後，系統只把勝出答案以純文字
寫回原答案格，再回讀核對，並保存逐題寫回紀錄。任何目標格被移動、刪除、改寫或結構改變時，整批停止，不寫入任何格子。

**Why this priority**: spec.md §1 明訂必須直接寫回同一份雲端試算表的原填空格，這是專題的核心驗收點，也是 Demo 必須展示的流程（DC-06）。

**Independent Test**: 用測試替身模擬雲端試算表，涵蓋正常寫回、衝突、權限不足、逾時與重試；再以真實的雲端試算表人工驗收並截圖。

**Acceptance Scenarios**:

1. **Given** 已結束的活動有中文、含換行與 `=1+1` 開頭的勝出答案，**When** 老師預覽並確認寫回，**Then** 原答案格顯示原文純文字（不會變成公式），其他文字與格式不變，無人作答的格子維持原標記（AC-12）。
2. **Given** 兩個單題與一個三題題組的標記分散在不同工作表與列欄，**When** 寫回，**Then** 每個勝出答案各自寫入它自己的原格（AC-17），換成另一份版面不同、題號不連續的試算表時也寫到新位置（AC-02）。
3. **Given** 匯入後有目標格被移動、刪除、改寫，或工作表被刪除、插入列欄、合併格子，**When** 老師預覽或寫回，**Then** 系統指出衝突的題號、格位與原因，整批停止、不寫入任何格子，並提示恢復原結構或另建活動重新匯入（AC-13）。
4. **Given** 寫回時權限不足、Google 回報失敗或逾時，**When** 老師查看結果，**Then** 系統逐題顯示失敗或「待核對」，不會回報整批成功，活動結果保持不變（AC-14）。
5. **Given** 前一次寫回逾時或部分完成，**When** 老師再次預覽並寫回，**Then** 系統先核對線上值：已是相同內容的格子視為成功、不重寫；仍是原標記的格子才寫入；被外部改成其他內容的格子視為衝突、不覆寫（AC-14）。
6. **Given** 整批已成功寫回，**When** 老師重複寫回，**Then** 系統辨識所有格子都已是相同內容，回報成功且不再寫入（AC-14）。
7. **Given** 同一場活動的寫回正在進行，**When** 另一個分頁也要求寫回，**Then** 第二個要求被拒絕並說明原因。

### User Story 3 - 下載 CSV 結果（Priority: P3，#15）

活動結束後，老師可以下載一份 CSV，內容與結果頁相同：每筆受理依題目展開成多列，無人作答的題目也有一列；
編碼與換行讓常見的試算表軟體能正確開啟中文；答案中的公式開頭字元會加上防護，避免開啟時被當成公式執行。

**Why this priority**: CSV 是必做的額外匯出（spec.md §1），但不取代線上寫回，因此排在寫回之後。

**Independent Test**: 準備含中文、引號、逗號、換行、公式開頭字元與無人作答的結果，下載 CSV 後逐欄比對，並以實際的試算表軟體開啟。

**Acceptance Scenarios**:

1. **Given** 已結束的活動，答案含中文、引號、逗號與換行，且有無人作答的題目，**When** 老師下載 CSV，**Then** 檔案為 UTF-8（含 BOM）、CRLF 換行，欄位與順序固定，轉義正確，排序與結果頁一致，無人作答題各有一列（AC-19）。
2. **Given** 答案或組名以 `=`、`+`、`-`、`@` 開頭（去除前導空白後），或有前導 tab、CR、LF，**When** 老師下載 CSV，**Then** 這些欄位前面加上單引號，資料庫中的原值不變；以實際試算表軟體開啟時不會執行公式（AC-20）。
3. **Given** 學生工作階段、未登入者，或活動尚未結束，**When** 要求下載 CSV，**Then** 一律拒絕（AC-19）。

---

### Edge Cases

- **全部無人作答**：結果頁每個單位都標示「無人作答」；寫回預覽顯示沒有需要寫回的答案，不呼叫寫入；CSV 每題一列、`is_winner` 為 false。
- **重複或並行結束**：只有第一次結束生效並保存一次結果；之後的結束要求以階段錯誤拒絕。
- **結束與送出並行**：結束生效後受理的送出被拒絕（SF-03 已保證），結果只包含結束前已受理的送出。
- **工作表改名**：目標仍以工作表本身識別，改名不算衝突；預覽顯示目前的名稱。
- **目標格內容恰好等於要寫入的答案**（例如之前寫入成功但回覆遺失，或有人手動填入相同內容）：視為「已是相同內容」，不重寫。
- **寫回途中伺服器重啟或連線中斷**：尚未確認的格子在紀錄中為「待核對」，下次寫回會先核對線上值。
- **整份試算表被刪除、取消共用或 Google 配額用盡**：明確告知失敗原因，不回報成功，結果不變。
- **公平模式活動**：最終順位由 SF-05 計算；在 SF-05 完成前，系統不得以速度規則替公平模式活動保存結果（結果一經保存不可修改）。
- **學生工作階段已改加入其他活動**：只能看到目前所屬活動的結果。

## Requirements *(mandatory)*

### Functional Requirements

**結果保存與檢視（US1）**

- **FR-001**（FR-06、§4、AC-11）：老師結束活動時，系統 MUST 在與狀態變更相同的不可分割步驟中保存每個單位的最終結果。速度模式下，每個單位依伺服器受理順序給予順位，第 1 名為勝出；題組單位每筆送出共用一個順位；無人作答的單位沒有結果紀錄，畫面明示「無人作答」。
- **FR-002**（§4、AC-10）：保存結果失敗時，系統 MUST 讓整個結束失敗並維持搶答中，不得留下部分結果；結束生效後受理的送出不列入結果。
- **FR-003**（FR-06）：活動結束後，老師與該活動的各組 MUST 能查看每個單位（依固定順序）與組內每一題：各組已受理答案、實際受理順序、最終順位、勝出組與答案、受理時間及活動模式。
- **FR-004**（FR-06、AC-11、AC-15）：結果 MUST 固定，系統不提供新增或修改結果的操作，資料層也拒絕任何修改；伺服器重啟後結果不變。
- **FR-005**（FR-05、AC-09、AC-16）：活動結束前，學生取得的頁面、API、即時事件與錯誤回覆 MUST NOT 包含任何結果或其他組的資料；結束後只有該活動的組別可以看到結果，其他活動的學生不行。
- **FR-006**（§3、FR-03）：活動結束時，已連線的老師與學生畫面 MUST 自動顯示結果，不需手動重新整理；重新連線後取得相同的結果。
- **FR-007**（§4、§9.1）：結果頁、Sheets 寫回與 CSV MUST 使用同一份保存的結果並標示模式。公平模式的順位計算由 SF-05 提供；在那之前，系統 MUST 拒絕以速度規則替公平模式活動保存結果。

**線上寫回原 Google Sheets（US2）**

- **FR-008**（FR-07、FR-01）：只有老師 MUST 能在活動結束後預覽與寫回；學生與未登入者的要求一律拒絕。
- **FR-009**（FR-07）：預覽 MUST 逐題列出題號、勝出組、答案、目標（工作表目前名稱與格位），以及重新讀取線上試算表後的狀態：可寫入、已是相同內容、衝突（含原因）或無人作答不寫入。預覽不得修改試算表。
- **FR-010**（FR-07、AC-13）：系統 MUST 在預覽時與實際寫入前各重新讀取一次目標格的值與結構。目標只有在工作表仍存在、格子仍在範圍內且未被合併，而且內容仍是原標記或已是本次要寫入的相同內容時才通過；其他情況都是衝突。
- **FR-011**（FR-07、AC-13）：只要有任一目標衝突，系統 MUST 停止整批寫回、不寫入任何格子，並列出衝突的題號、格位與原因，提示恢復原結構或另建活動重新匯入；不得沿用舊座標盲寫，也不得自行猜測新位置。
- **FR-012**（FR-07）：寫入前 MUST 要求老師確認已暫停其他人編輯這份試算表；完成後提醒老師恢復編輯。系統不宣稱在任意外部並行編輯下都不會覆寫。
- **FR-013**（FR-07、AC-12、AC-17、AC-02）：系統 MUST 只修改勝出答案的目標格，以純文字（RAW）寫入受理時的原文（含換行，`=1+1` 不變成公式）；題組各題各自寫回原格；保留其他文字與格式；無人作答的格子不變。同一次寫回以單一批次送出。
- **FR-014**（FR-07、AC-14）：寫入後 MUST 回讀目標格核對；只有回讀內容與寫入內容一致的格子才算成功。
- **FR-015**（FR-07、§6 Export、AC-14）：每次寫回 MUST 保存逐題紀錄：時間、目標、寫入內容與結果（成功、已是相同內容、衝突、未寫入〔整批因衝突停止〕、失敗、待核對）及原因。只有全部目標都成功或已是相同內容時，才可回報整批成功；權限不足、失敗、逾時或部分完成都必須如實顯示。
- **FR-016**（FR-07、AC-14）：無法確定是否已寫入（例如逾時或回覆遺失）且回讀也無法確認時，該題 MUST 顯示「待核對」。下次寫回先核對線上值：相同內容視為成功、不重寫；仍是原標記才寫入；外部改成其他內容視為衝突、不覆寫。
- **FR-017**（FR-07）：同一場活動的寫回 MUST 互斥；進行中再次要求時拒絕並說明。寫回途中中斷（例如伺服器重啟）時，尚未確認的題目記為「待核對」。
- **FR-018**（FR-07、§7）：寫回 MUST NOT 修改活動結果；與 Google 連線時顯示進行中狀態，網路、授權、配額或 API 失敗時明確說明原因，不得以假資料冒充成功。

**CSV 結果匯出（US3）**

- **FR-019**（FR-09、AC-19）：只有老師 MUST 能在活動結束後下載 CSV；學生、未登入者或未結束的活動一律拒絕。
- **FR-020**（FR-09）：CSV MUST 以 UTF-8（含 BOM）編碼、CRLF 換行，第一列為固定欄位 `activity_id, mode, unit_id, question_id, group_name, answer, accepted_at, accepted_order, rank, is_winner`。
- **FR-021**（FR-09）：每筆受理 MUST 依題目展開為每題一列，依單位固定順序、最終順位、組內題序排序；時間為 UTC ISO 8601；`is_winner` 為 `true` 或 `false`。`unit_id` 單題為 `Q:<題號>`、題組為 `G:<題組代號>`（AC-26；資料庫與 JSON API 仍使用內部 ID），`question_id` 為原題號。
- **FR-022**（FR-09）：無人作答的題目 MUST 仍有一列，`group_name`、`answer`、`accepted_at`、`accepted_order`、`rank` 留空，`is_winner` 為 `false`。
- **FR-023**（FR-09、AC-19）：含逗號、雙引號、CR 或 LF 的欄位 MUST 以雙引號包住，內部雙引號重複一次。
- **FR-024**（FR-09、AC-20）：來自使用者輸入的欄位（組名、答案、題號與單位代號）去除前導空白後若以 `=`、`+`、`-`、`@` 開頭，或原值有前導 tab、CR、LF，MUST 在原值前加一個單引號；資料庫中的原值不變。
- **FR-025**（FR-06、FR-09、§4）：結果頁與 CSV 的實際受理順序（`accepted_order`）MUST 為伺服器分配的受理序號：整場活動由 1 起跨單位遞增，題組一筆受理用一個序號，與 SF-03 教師監看的「受理順序」是同一個數字；`rank` 為單位內的最終順位，兩者分開呈現。

### Key Entities *(include if feature involves data)*

- **結果（Result）**：每筆已受理送出一筆，記錄所屬單位、最終順位與是否勝出；與結束狀態一起保存，之後不可修改。實際受理順序來自送出本身的伺服器受理序號。
- **單位結果檢視**：依單位固定順序整理各題的受理清單、勝出組與答案；沒有任何受理的單位標示為無人作答。
- **寫回紀錄（Export）**：每次寫回一筆，記錄活動、開始與結束時間、整批結果；逐題紀錄記錄題目、目標（試算表、工作表、格位）、寫入內容、狀態（成功、已是相同內容、衝突、未寫入、失敗、待核對）與原因，供查核與安全重試（spec.md §6）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：在 1 位老師、10 組、20 題的本機情境下，老師確認結束後 2 秒內，所有已連線的老師與學生畫面都顯示完整結果。
- **SC-002**：結果頁、寫回內容與 CSV 的勝出組、答案、順位 100% 一致；伺服器重啟前後結果完全相同。
- **SC-003**：在格位移動、刪除、改寫，以及刪除工作表、插入或刪除列欄、合併格子等測試情境中，被寫入的格子數為 0。
- **SC-004**：在權限不足、失敗、逾時與部分完成的測試情境中，系統回報整批成功的次數為 0；重試時被外部改成其他內容的格子被覆寫的次數為 0。
- **SC-005**：以實際的試算表軟體開啟 CSV 時，中文正確顯示、沒有任何公式被執行，資料列數等於「各單位受理數 × 單位題數」的總和加上無人作答的題數。
- **SC-006**：學生在活動結束前取得結果或其他組資料、或在任何時候下載 CSV 與觸發寫回的成功次數為 0。
- **SC-007**：老師從結果畫面開始，最多三個步驟（預覽、確認已暫停編輯、寫回）即可完成寫回，並看到逐題結果。

## Assumptions

- 模式選擇由 SF-05（#19）提供；SF-04 完成時，透過介面建立的活動都是速度模式。公平模式的順位由 SF-05 計算後，沿用本功能的結果保存、檢視、寫回與 CSV。
- 老師在建立下一場活動前完成寫回與下載 CSV。SF-01 的活動清單只保留最近一場已結束的活動，歷史搜尋不在本版範圍（spec.md §10）。
- 每場活動的題目來自同一份雲端試算表（SF-02 匯入），服務帳戶已有該試算表的編輯權限（spec.md §7）；寫回沿用 SF-02 的 Google 連線與授權。
- 目標格是否「仍是原標記」以去除前後空白後與匯入時的標記相同為準，與 SF-02 解析標記的規則一致。
- 任一目標衝突就整批停止，是為了保留所有原標記，讓老師恢復結構後重試，或另建活動重新匯入。
- 外部人工編輯不受系統控制，讀取與寫入之間仍可能有競態；系統以老師確認暫停編輯、寫入前重新核對與寫入後回讀降低風險（spec.md FR-07）。
- 在本功能上線前已結束、但沒有保存結果的速度模式活動，系統依同一速度規則補齊結果，讓這些活動也能查看與匯出。
