# SF-03 驗證方式

## 自動驗證

```bash
npm ci
node --test 'tests/{unit,integration}/realtime-buzzer/*.test.js'
npm test
```

需要 Node.js 24 以上。測試以固定時鐘及專用 SQLite 證明同時間戳排序、重送去重、題組原子性、結束競態、組別快照隔離與重啟恢復。實際 loopback HTTP／SSE 測試覆蓋 1 位教師、10 組學生、20 題。測試證據及其範圍見[驗收紀錄](acceptance.md)。

## 瀏覽器複驗

1. 用 `npm run setup:teacher` 設定本機教師密碼，再用 `npm start` 啟動。依[服務帳戶設定](../../README.md#google-sheets-服務帳戶)準備已授權的雲端試算表，並參照 [SF-02 驗收紀錄](../002-sheets-import/acceptance.md)準備至少兩個單題與一個題組。
2. 在 `http://127.0.0.1:3000/teacher/` 建立活動並確認匯入。用兩個獨立的瀏覽器工作階段開啟 `/student/`，用同一加入碼加入甲、乙組。準備中只能看到題號與文字狀態，教師開啟後兩組應在兩秒內看到搶答中。（AC-04、AC-09）
3. 讓甲組先送第一個單題、乙組先送第二個單題。另送一份完整題組，並檢查缺題會被拒絕。教師核對各單位的暫定勝出與受理順序，並確認答案中 `<script>` 字樣原樣顯示。學生只可看到本組的受理紀錄。（AC-05、AC-08、AC-09、AC-16、AC-18）
4. 保留同一個學生工作階段，刷新或重連，核對受理識別。教師先取消結束，再確認結束。`CLOSED` 後的 POST 會被拒絕，原受理紀錄仍可從學生快照取得。以同一 SQLite 資料庫重啟後，再核對識別與原答案。（AC-07、AC-10、AC-15）

過去的 Chromium 測試使用明示的 Sheets 測試替身。真實雲端試算表結果依原課程驗收步驟留證。
