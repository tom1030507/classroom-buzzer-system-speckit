# SF-03 即時搶答

**負責人** tom1030507 · **分支** `feat/003-realtime-buzzer` · **實作 PR** [#26](https://github.com/tom1030507/classroom-buzzer-system-speckit/pull/26)

依[產品規格 §9.1](../../spec.md)，SF-03 涵蓋 FR-03～FR-05 與 FR-08 的送出部分。SF-01 提供教師及學生組別工作階段，SF-02 提供已確認的單題與題組。SF-04 #14 負責在結束交易保存最終結果，SF-05 擴充公平排序。

## 使用者情境

### US1 教師開啟與結束活動（P1，#10）

- 教師確認匯入至少一題後開啟活動。已加入的學生收到「搶答中」並開始作答，其他學生無法在此時加入新組。無題目或畫面上的匯入已被另一分頁取代時，開啟請求失敗，活動維持準備中。（FR-03、AC-04）
- 教師確認結束後，已受理的答案保留，結束生效後抵達受理流程的送出一律拒絕。連線中斷時畫面顯示狀態，重連取得最新活動階段及自己可見的紀錄。（FR-03、AC-10、AC-15）

### US2 學生作答並取得受理紀錄（P1，#11）

- 已加入的組別可在開啟階段送出一個單題或完整題組。題組少題、多題、題號不屬於該單位、有重複題號或任何一題內容不合法時，整組拒絕。（FR-04、FR-08、AC-08、AC-18）
- 同一組在開啟階段雙擊、有效重試或更改答案後再次送出同一單位，均取得第一次有效送出的答案及同一受理識別。若重試時活動已結束，改從活動快照查看原受理紀錄。（FR-03、FR-04、AC-07、AC-10、AC-15）

### US3 教師監看，學生查看本組紀錄（P1，#12）

- 教師可依題號查看各組是否送出、已受理答案和單位內受理順序。速度模式顯示每單位的暫定勝出組，公平模式顯示「結束時計算」。（FR-05、FR-08、AC-05、AC-06）
- 準備及搶答中的學生頁面、API、即時事件及錯誤只提供自己的組別資料和受理紀錄。收到受理回覆或帶有該組受理紀錄的伺服器快照後，畫面才顯示「已受理」。助教或教師可用鍵盤操作並核對答案中的標籤字樣按原文呈現。（FR-03～FR-05、AC-09、AC-16）

## 功能需求

- **FR-03 活動控制與同步**。由後端驗證教師工作階段，以 `PREPARING → OPEN → CLOSED` 順序轉移。開啟需要有題目，教師頁必須以已確認的匯入版本開啟。結束需要明確確認。斷線時顯示文字提示，重連還原最新快照。（AC-04、AC-10、AC-15、AC-16）
- **FR-04 作答與送出**。依組別工作階段、階段、單位、題號及答案內容驗證送出。第一次有效送出取得伺服器分配的活動內唯一遞增序號。`OPEN` 期間的有效重送取得原紀錄。`CLOSED` 後的送出一律回 `INVALID_PHASE`，包含先前已受理單位的重送。先前的受理紀錄可從 `GET /api/student/activity` 或學生 SSE 快照取得。（AC-04、AC-06～AC-08、AC-10、AC-15）
- **FR-05 教師監看與學生隱私**。教師查看各組已受理的內容與順序，速度模式以該單位最早受理者為暫定勝出，公平模式等結束時計算。學生資料由後端按工作階段過濾，答案和組名以純文字呈現。（AC-05、AC-06、AC-09、AC-16）
- **FR-08 題組原子送出**。題組成員必須各出現一次且全部有效，題組共用一筆受理序號。驗證、去重、序號分配與所有答案在同一交易內完成，任一答題寫入失敗便回滾整筆。（AC-05、AC-07、AC-08、AC-10、AC-18）

每題最多 1,000 個 Unicode code point，必須至少含一個非空白字元。保留原文與換行，包含答案前後空格。全形空白列入空白判定，拒絕無法忠實轉成 UTF-8 的未配對 surrogate。學生受理識別不能透露受理順位。（FR-04、FR-05、FR-08、AC-07～AC-09、AC-18）

## 成功準則

- **SC-001** 以 1 位教師、10 組學生、20 題的本機情境量測，活動開啟在 2 秒內送達所有既有連線，一般送出在 2 秒內取得伺服器回覆。（FR-03、FR-04、AC-04）
- **SC-002** 兩組先答不同單位，各自成為該單位的速度模式暫定勝出者。同一單位的兩筆有效送出即使伺服器時間戳相同，序號與暫定勝出仍唯一。公平模式顯示「結束時計算」。（FR-04、FR-05、AC-05、AC-06）
- **SC-003** 同組同單位在 `OPEN` 並行有效送出及重試只留一筆，回覆的受理識別及答案一致。無效內容、題號、單位或身分不新增紀錄。（FR-04、FR-08、AC-07、AC-08）
- **SC-004** 比對兩組各自的 HTTP、SSE 及錯誤回覆，另一組送出前後不會出現其組名、答案、狀態、數量、序號、順位或勝出資料。學生的教師端請求須被拒絕，答案中的 HTML 字樣原樣呈現。（FR-05、AC-09、AC-16）
- **SC-005** 結束與送出並行時，依伺服器交易先後保留先受理資料或拒絕送出。結束後同組重送已受理單位仍回 `INVALID_PHASE`，其快照仍可讀取原受理紀錄。故意中斷題組第二題寫入時，新增受理、序號與答案皆回滾。（FR-03、FR-04、FR-08、AC-10、AC-18）
- **SC-006** 同一學生工作階段刷新、重連或伺服器以原資料庫重啟後，可讀取原活動階段和同一受理識別與答案，資料庫只保留一次受理。（FR-03、FR-04、AC-15）
