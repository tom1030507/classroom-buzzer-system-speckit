# SF-03 驗收紀錄

HTTP 情境位於 [`tests/integration/realtime-buzzer/realtime-buzzer.test.js`](../../tests/integration/realtime-buzzer/realtime-buzzer.test.js)，交易情境位於 [`tests/unit/realtime-buzzer/submissions.test.js`](../../tests/unit/realtime-buzzer/submissions.test.js)。執行 `npm test`。

- **AC-04**。1 位教師、10 組學生、20 題，使用實際 loopback HTTP／SSE 驗證開啟同步與一般作答在 2 秒內完成。另驗證空活動不能開啟、舊匯入格位版本不能開啟新匯入、準備中不能作答以及結束需要確認。
- **AC-05、AC-06**。兩個單位分別由 A、B 勝出。同時送出共用固定伺服器時鐘，受理序號、順位和暫定勝者仍唯一。
- **AC-07、AC-08**。重試回傳原受理識別及答案。空白、超長、無效 Unicode 或單位、冒用他組均不建立受理紀錄。1,000 個 Unicode code point 的字串可送出，原文與換行保留。以 261 題、每題 1,000 個 emoji 驗證大型合法題組的 HTTP 傳輸。
- **AC-09、AC-16**。準備中與搶答中的學生 API、SSE 和錯誤回覆只提供該組可見資料。學生無法連教師 API 或事件。兩組資料不同且另一組送出時不發送學生快照。
- **AC-10、AC-18**。題組缺題、多題、不合法或嘗試拆題都會拒絕。並行重送只受理一次，故意中斷題組第二題寫入時整筆回滾。結束與送出競態時以交易先後為準。
- **AC-15**。刷新／重連取得自己的最新紀錄；以檔案型 SQLite 重啟後，仍可驗證原組 Cookie、讀回快照與重用原受理識別。

## 瀏覽器驗證

2026-11-19 以 Chromium、三個獨立瀏覽器工作階段及實際本機 HTTP／SSE 驗證。教師以鍵盤登入，使用 Sheets 測試替身匯入五題三單位，確認可調整工作表順序。兩組學生各自加入，開啟時同步顯示「搶答中」。甲組送出含 `<script>` 的文字，教師與甲組均只看見原文字串，DOM 沒有新增 script 元素，乙組看不到甲組的名稱與答案。乙組整組送出三題；教師看到兩個單位各自的暫定勝出組。甲組刷新後原受理紀錄仍存在。取消結束時活動仍開啟，確認後兩組都同步顯示「已結束」。

以同一教師工作階段開兩個分頁，第二頁確認更換試算表後，第一頁即時顯示新匯入。作答送達後，教師監看表格保留原鍵盤焦點。
